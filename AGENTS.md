# Architecture rules
- Reuse shared email and street-address schemas in pure preorder validation with regression tests; this keeps live errors and pre-submit checks consistent without changing the external order service.
- Use local libaddressinput country metadata and libphonenumber in the preorder's pure international-address helper; keep country-specific requirements and Unicode address validation separate from sizing-kit rules and preserve the external order payload.
- Keep photo-sizing geometry and reliability gates in the ring-sizer function's pure measurement module, with Vitest regressions under src/test; this separates arithmetic verification from unvalidated anatomical fit assumptions.
- A palm-photo result must not show shoppers a US size unless sizing_settings.show_sizes is on; a database trigger only allows that after a passing /bench run on the current chart, because untested estimates misled real users.
- Gate sizing-camera access with the shared device-identity helper, not viewport width, so resizing a laptop window cannot enable phone-only capture.
- Keep the sizing FAQ in a dedicated routed page using the shared header, footer, SEO and accordion components to preserve site navigation and accessible question controls.
- Render the full-screen sizing camera in a body portal above site overlays so cookie notices and parent stacking contexts cannot block its shutter or cancel controls.
- Keep the photo/check/fit-confirmation stages in the shared RingSizer, with automatic card detection and no manual corner step; both entry pages must use the same simple flow.
- Keep physical-measurement guidance shared across shopping and sizing pages, with pure chart conversion and repeat-reading checks tested separately; never treat illustrative screen dimensions as a real ruler or chart matches as verified sensor-ring fit.
- Load third-party measurement tutorials only on explicit watch clicks, using privacy-enhanced embeds with publisher credit and a direct viewing fallback; avoid silently loading external video services.
- Open the static printable sizer through a same-origin fetch and an in-page blob preview, not a hardcoded live-domain redirect, so preview restrictions cannot block the external navigation.
- Keep interactive paper-measurement imagery in a shared visual component and label it illustrative; image hotspots explain technique but must never supply a shopper's measurement.
- Store sizing-kit shipping requests through a server-validated function with admin-only reads; a request must reach the fulfillment team rather than opening an email app.
- Adapt sizing-kit first/last names and country-aware phone inputs to the existing request payload in a tested client helper; this preserves fulfillment storage while using international phone metadata.
- Serve final campaign media through CDN pointers in a dedicated download catalog; use corrected final versions and fetch blobs for same-origin downloads.
